# 插件安全边界

## 能提供的隔离

- 有后端的私有实现可用独立二进制交付，宿主公开源码不必包含其业务逻辑；纯前端仍交付可读取的静态资源。
- 进程协议避免 Go 动态链接和共享内存 ABI。
- 包签名和文件哈希防止未授权替换。
- UI 使用短时 URL、独立 Bridge Token 和 sandbox iframe。
- 插件故障时 OAuth 插件路径失败关闭，不静默切回另一种网络行为。
- schema 2 业务资源会话区分用途，绑定包代次、入口、可信用户/角色与 TokenVersion；每次读取复核启用和身份，iframe 不获得 JWT。
- 通用 Backend 反向宿主调用同时检查清单能力与本次短时授权，不接受插件自报调用者或其他插件身份。

## 不能提供的保证

- 闭源二进制仍可能被逆向分析。
- 子进程不是操作系统沙箱。
- 插件拥有 Sub2API 服务用户可访问的文件、环境变量和网络权限。
- 包签名证明发布者身份，不证明实现无漏洞或符合 Provider 条款。

HostService 权限只限制宿主提供的接口，不能限制恶意原生进程经服务用户权限直接读文件或访问网络。纯前端没有原生运行时，但仍必须遵守受限 iframe 和消息合同，不能把 Bridge 扩大成任意 DOM、脚本或 API 代理。

## 部署要求

- 官方 OpenAI Transport 使用宿主内置公钥；只向 `plugins.trusted_publishers` 添加经过审核的第三方公钥。
- 使用专用低权限系统用户运行 Sub2API。
- 限制该用户的文件权限、出站网络和环境变量。
- 不向插件环境注入无关密钥。
- 对插件升级保留旧包和回滚流程。
- 记录安装、启用、停用、配置和删除操作，但不记录配置明文。
- 核对通用插件声明的实际权限，特别是后台工作、存储写入和全站用户邮箱；普通用户不能替插件授予这些权限。

## 敏感数据

schema 1 Transport 会处理真实 OAuth Authorization 请求头，必须避免将请求头、请求体、代理凭据和上游敏感响应写入日志或诊断消息。UI 配置中不应出现 OAuth Token。schema 2 不因实现 Backend 获得旧账号目录或 OAuth 凭据；用户创建观察需要独立能力，普通 user 方法不能读取全站用户，当前邮箱还需 users.email.read.v1。

通用 Backend 必须完成 Host API 3 初始化，不能沿用旧 Transport 的可选握手降级。每次 KV/观察调用携带当前 Invoke/RunOnce 的 access_token，生命周期调用不给业务授权；结束、停用或换包后旧授权无效。user 方法的 KV 包括管理员调用时也按当前用户隔离，admin/background 使用插件共享空间；只读方法不能写入。

宿主调用审计保留调用者、插件/方法、request_id、状态及耗时摘要，不保存任意 payload 或配置 body。插件日志同样不得包含这些敏感内容或授权 token。业务错误先脱敏再返回；写操作派发后超时/断连不能声称未执行或自动重试。详细权限、后台回收与完成记录边界见[通用契约](generic-plugins.md)和[示例说明](../examples/README.md)。
